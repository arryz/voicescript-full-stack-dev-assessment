# Implementation Plan: Type-Safe API and Data Layer Refactor

**Branch**: `002-trpc-prisma-refactor` | **Date**: 2026-06-01 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/002-trpc-prisma-refactor/spec.md`

## Summary

Replace all Express REST route handlers with a tRPC v11 router (end-to-end type-safe API, compile-time contract enforcement) and replace raw `better-sqlite3` queries with the Prisma ORM (single schema source of truth, versioned migrations, auto-generated types). All existing domain logic — workflow state machine, business rules, seed data — is preserved unchanged.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Primary Dependencies**:
- Backend: tRPC v11 (`@trpc/server`), Prisma 5.x (`@prisma/client`), Express 4 (tRPC adapter), Zod 3 (input validation)
- Frontend: tRPC v11 (`@trpc/client`, `@trpc/react-query`), TanStack Query v5 (`@tanstack/react-query`)

**Storage**: SQLite via Prisma (replaces direct `better-sqlite3`); `prisma migrate` manages versioned migrations
**Testing**: Jest + tRPC `createCallerFactory` (integration tests invoke procedures directly without HTTP)
**Target Platform**: Node.js 20+ (backend), Browser/Vite (frontend)
**Project Type**: web-service + frontend SPA (two-server setup)
**Performance Goals**: Compile-time contract mismatch detected in <5s (SC-003)
**Constraints**: Zero runtime type errors (SC-001); all existing tests pass (SC-002); fresh-install setup in <3 min (SC-004); zero hand-written DB entity type definitions (SC-005)
**Scale/Scope**: Single-developer assessment; small dataset (4 reporters, 2 editors, variable jobs)

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Principle IV: routes + controllers collapsed into tRPC router procedures | tRPC's end-to-end type inference requires the procedure definition to be the single authoritative source of the API contract; a separate controller shim breaks the type chain | Splitting the procedure body into a controller would reintroduce the same runtime-only coupling that the refactor is designed to eliminate (FR-001) |
